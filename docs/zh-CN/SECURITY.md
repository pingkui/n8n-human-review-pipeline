# 安全与隐私说明

这是演示,不是加固过的服务。下面是已知的情况,以及哪些覆盖了、哪些没有。

## 恢复链接就是一种权限
谁拿到某份草稿的恢复链接,谁就能批准、要求修改或拒绝它。只通过私密渠道发送。生产环境里要在 n8n 的 webhook 端点前面加认证。本仓库没有加。

## 审核页面没有登录
`deploy/inbox.py` 只监听 `127.0.0.1`,没有认证。能访问它的人可以提交请求(会产生模型调用费用)并批准草稿。请通过 SSH 隧道访问,或者在前面加上认证、限流和消费上限。它输出的所有内容都做了 HTML 转义,所以模型或请求方的文字无法在页面里执行脚本。

## 请求方的文字会进入提示词
`topic` 和 `facts` 是任何调用 webhook 的人写的自由文本,会被插入模型的提示词,所以他们可以试图引导模型。限制损害的因素:模型不能发布、每份草稿都有人审核、检查会标出禁用词和没有提供过的数字。没有覆盖的:草稿仍可能具有误导性却不触发任何检查,而且数字检查只是比较字符串。

## 密钥与环境
- `LLM_API_KEY` 通过 `$env` 到达节点,这需要 `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`。这个设置会让同一个 n8n 实例上的任何工作流都能读取环境变量,所以不要和你不信任的工作流共用同一个实例,或者改用 n8n 凭据。
- `deploy/.env` 里存放密钥;它在 `.gitignore` 里,权限应为 600。绝不要提交它。

## 个人和机密数据
主题、事实和草稿会发给你的模型服务商,以及 `NOTIFY_URL`、`PUBLISH_URL`、`AUDIT_URL` 指向的任何地方。服务商是否保留这些数据或用于训练,取决于你和它的合同,与本仓库无关。对机密材料,请使用你读过其条款的服务商和套餐。审计记录只为已发布的文章保存最终文字。

## 发布到某个网络
`PUBLISH_URL` 是通用的。如果你把它接到社交网络,请遵守该平台的条款和频率限制。自动化互动(点赞、评论、私信)可能导致账号受限;本工作流不做这些。

## 没有做的
没有认证、没有限流、审计日志没有保留策略、调用失败时没有重试或告警。
